# Core contracts

PLAN step 10 (#7). These are the shapes that something outside the web app depends on:
- the Swift port (`native/RouteIQCore`, #33);
- the iPhone shell (`native/shell`) and its Swift plugin;
- the files the app ships and the data it keeps on the device.

They are versioned together under one number:

```ts
import { CORE_CONTRACT_VERSION } from './src/core/index.ts' // src/core/contract.ts
```

**Current version: 7** (Nov 12, 2026: version 6 plus each check's route count and saving on `LiveState.lastDecision`, #175). The Swift port matches it, except the drive log and the place book (#33);
see [Who matches which version](#who-matches-which-version).

## What is in the contract

The declarations below are read straight from the TypeScript source, together with every type
they refer to, directly or not. They are kept, with comments and layout dropped, in
[`contracts/core-contract.json`](contracts/core-contract.json) (`declarations`), with a hash of
the whole surface. That file is the machine-readable type snapshot: about 50 declarations, each
on one line.

| Contract | Root types | Defined in | Used by |
| --- | --- | --- | --- |
| Routes | `RouteCandidate` (with `segmentTraffic` and `source: 'probe'`), `RouteSignal` | `src/core/types.ts` | everything downstream of the Directions adapter; `Types.swift` |
| Signal tiles | `OsmSignalTile` | `src/providers/osm/adapter.ts` | `public/seed/osm-signals/<tileId>.json`, the device cache; `SignalBundle.swift` |
| Signal bundle index | `OsmBundleIndex` (version 2, `TileRows`) | `src/providers/osm/bundle.ts` | `public/seed/osm-signals/index.json`; `SignalBundle.swift` |
| Place book | `PlaceBook` | `src/core/places.ts` | localStorage `routeiq.places.v1`, stored with `version: 1` |
| Drive log | `DriveLog` (`DriveRecord`, `LoggedSwitch`) | `src/core/driveLog.ts` | localStorage `routeiq.drives.v1`, stored with `version: 1` (#107) |
| Reroute engine | `RerouteOptions`, `RerouteState`, `RerouteObservation`, `RerouteDecision` | `src/core/reroute.ts` | the simulated and live drives; `Reroute.swift` |
| Live drive | `LiveOptions`, `LiveState`, `LiveEvent`, `LiveEffect` | `src/core/live.ts` | `src/live/runner.ts`, a native shell running the same machine |
| Native plugin | `RouteIQNativePlugin` (`fix`, `locationError`, `tick`, `appState` events; `httpGet`, `httpCancel`; `NativeFix`) | `src/device/native/plugin.ts` | the iPhone shell's Swift plugin `RouteIQNative` |

The types these refer to come along automatically. Among them are `LngLat`, `Maneuver`,
`GuidanceStep`, `SegmentTraffic`, `CongestionLevel`, `RouteSource`, `TrackingOptions`,
`TrackingState`, `PositionFix`, `SpokenLine`, `RerouteCode`, `SavedPlace` and `StoredTrip`.
The list of roots and source files is `CONTRACT_ROOTS` and `CONTRACT_SOURCES` in
`tests/helpers/contractSurface.ts`.

### JSON Schemas

The formats that cross a file or a bridge have a JSON Schema (draft 2020-12) in
[`contracts/schemas`](contracts/schemas):

| Schema | What | Checked against |
| --- | --- | --- |
| `signal-tile.schema.json` | one bundled tile | every file in `public/seed/osm-signals` |
| `signal-index.schema.json` | the bundle's `index.json` | the shipped `index.json` |
| `place-book.schema.json` | the stored place book | `serializePlaceBook` output, empty and full |
| `native-bridge.schema.json` | plugin payloads: `fix`, `locationError`, `appState`, `httpGet` request, answer and error codes, the `startSimulatedRoute` request and its steps, the `share` request (`tick` has no payload) | sample payloads |

`tests/contracts.test.ts` checks two things:
- **The data:** the shipped tiles and index, and the stored place book, validate against their schemas.
- **The fields:** each schema names the same fields, with the same required ones, as the
  TypeScript type it stands for.

So a schema cannot drift from its type unnoticed. The schema files are hashed into the contract
too.

### Not in the contract

- **Defaults and rules.** The values in the `DEFAULT_*` objects (`DEFAULT_REROUTE_OPTIONS`,
  `DEFAULT_TRACKING_OPTIONS`, ...) and the rules themselves are pinned by the unit tests, which
  are the spec for the port, and by the README thresholds tables. A changed default does not
  change the version. It changes a test.
- **The Mapbox Directions response.** It is Mapbox's contract. `parseDirections` and its
  fixtures in `tests/fixtures` are the spec for reading it.
- **UI-only types:** views, panels, hooks.

## Changing a contract

Any change of shape changes the version, however small:
- a field added, removed or renamed;
- a field made optional or required;
- a word added to or removed from a union;
- a schema edited.

There is no "compatible" change: the Swift side is generated by hand, and it has to know.

1. Make the change.
2. Bump `CORE_CONTRACT_VERSION` in `src/core/contract.ts`.
3. Regenerate the snapshot:

   ```bash
   UPDATE_CONTRACT=1 npx vitest run tests/contracts.test.ts
   ```

   This refuses to run while the version is unchanged. It records the new version and its hash
   in `history`.
4. Add a line under [Changes](#changes), and update `native/RouteIQCore/README.md` if the port
   is affected.

`npx vitest run` (and so `/verify` and CI) fails on a change of shape without a bump, and names
the declarations that changed.

**The check itself:**
- **Tokens, not a compiler:** TypeScript 7 ships no JavaScript compiler API, so
  `tests/helpers/contractSurface.ts` reads the declarations with a small tokenizer of its own.
- **Forms it reads:** `interface X { ... }` and `type X = ...` at the top level of a file.
- **Layout is ignored:** comments, line breaks, semicolons, a trailing comma and a leading `|`
  make no difference. A comma between interface members does, but the codebase never uses one.
- **A name declared in two files** is resolved the way TypeScript does: the file's own
  declaration first. Two exported declarations of one name are an error.

  age out); `RerouteState.lostAtSec` (the time of each counted "no route" answer; `lostPolls` is
  its length). For the port: see the Swift-port note on PR #109.
- **4** (Nov 12, 2026, #29, #30, #71): the live drive's robustness fixes.
  `LiveOptions.requestTimeoutSec` (a request not answered in time is a failed answer),
  `LiveState.pickedAtMs` and the Start event's `routeFetchedAtMs` (a drive started on the
  plan's route counts the plan's answer as its last check). No field removed or renamed; the
  Swift port is not affected beyond these live-drive shapes.
- **5** (Nov 12, 2026, #107): `LiveSwitch.savingSec` (the saving the engine claimed for a switch, null when
  none); the private drive log `DriveLog` (`DriveRecord`, `LoggedSwitch`, `LoggedSignals`, `DriveOutcome`)
  joins the contract as data kept on the device.
- **6** (Nov 12, 2026, #84): the live drive's switch moment, display data only; the reroute
  engine is unchanged. `LiveState.switchBanner` gains `atMs`, `beforeSec`, `afterSec` and
  `turnInM`, and its `text` is now the spoken line; `LiveState` gains `offer` (a faster route
  being confirmed) and `kept` (the calm banner after "Keep my route") and `declinedTurns`; `LiveOptions` gains `heldTurnMatchM`. The `keep-previous`
  event now also turns down a route that is still being confirmed.
- **7** (Nov 12, 2026, #175): `LiveState.lastDecision` gains `routes` (how many routes the
  check's answer had; null when none came back or the previous route was kept) and `savingSec`
  (the considered alternative's like-for-like saving, `RerouteAlternative.savingSec`; null when
  the engine could not compare). Read by the drive diagnostics; the reroute engine is unchanged.
